What it is

Static in, native out

The app stays a single self-contained HTML file. The kit wraps that file in a native shell — it never becomes a new codebase.

No backend, no network

Both deliverables run entirely offline. The EXE serves the app from a loopback port; the APK loads it from bundled assets.

One reusable workflow

Consuming repos check out drsamonline/app-builder in their workflow. Improvements to the kit reach every app at once.

Two independent jobs

EXE and APK build separately, so a broken Android toolchain never costs you the Windows release.

Both are attached to a GitHub Release on every push. A build published as a release asset is the artefact — the workflow log is not evidence that a real binary exists.

How a repo uses it

# .github/workflows/build-apps.yml — the whole integration
jobs:
  app:
    uses: drsamonline/app-builder/.github/workflows/build.yml@97cd6e65…
    with:
      app_name: my-app
      app_src: docs/play        # the folder holding index.html
      deploy_path: docs         # where Pages serves the landing from

Pin the ref. @main means every commit to this kit changes how your app builds, with no review and no record.

Signing

The APK is signed so it can be sideloaded without a warning you have to talk yourself out of, and the EXE is a real PE binary — not a renamed script. Platform targets are Windows, Linux and Android; there is no macOS or iOS build, by policy.
